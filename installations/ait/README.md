# AIT installation

The files the stack mounts when `INSTALLATION=ait` (in `vc-stack/.env` or the environment): `INSTALLATION=ait ./run-demo.sh`. Everything else in `vc-stack/` is the same for every installation. Certify's seed runs only on a fresh database, so switching a local stack from another installation needs `--wipe` (`INSTALLATION=ait ./run-demo.sh --wipe`), which also renews the signing key and `did:key`.

| File | Read by | Notes |
|---|---|---|
| `certify-csvdp-student.properties` | Certify (`csvdp-student` profile) | Certify's settings, including the authorization server (realm `inji`) and the Gateway data-provider plugin's six keys (below); `bootstrap.sh` rewrites `did-url` after a wipe |
| `certify_seed.sql` | Postgres, first start only | The `credential_config` row for `ait-transcript`, mounted after `vc-stack/certify_init.sql` |
| `keycloak-realm.json` | Keycloak (`--import-realm`) | Realm `inji`: one user per CSV `id`, the `wallet-demo` client, the test-only `smoke` client, the `ait_transcript_vc_ldp` scope. `bootstrap.sh` syncs the `wallet-demo` certificate into it |
| `gateway.env` | The Gateway (`gateway/`), through Compose's `env_file` | Its settings, listed below |
| `mimoto-issuers-config.json.template` | `data/render_mimoto_issuers_config.py` | Mimoto's issuer list (wallet test harness), with `${INJI_WEB_URL}` left to fill |
| `mimoto-issuers-config.json` | Mimoto, Inji Web | Rendered by `run-demo.sh` from the template, then patched by `bootstrap.sh`. Git-ignored |
| `adapter/student_identity_data.csv` | The mock adapter (`adapter/`, mounted read-only at `/data`) | Generated by `data/generate_csv.py` from `data/students.json`. Git-ignored. After the claim columns come `level`, `holds` (a JSON list), `conferralStatus` and `balance`, the eligibility attributes. To change a student's eligibility edit the file (or `eligibility` in `students.json` and regenerate): the adapter reads it on every request, no restart of anything |
| `smoke.json` | `vc-stack/smoke.sh`, `gateway/tests/test_issuances.py`, `vc-stack/test_inji_web_vc_readiness.py` | The installation's test fixtures, below |

The installation's own values:

- Keycloak realm: `inji`, with wallet client `wallet-demo`
- Test-only client `smoke`: public, direct-access grant, the `ait_transcript_vc_ldp` scope and a hardcoded `client_id` claim; only `vc-stack/issue_and_verify.py` (run by `smoke.sh`) uses it
- Scope: `ait_transcript_vc_ldp`
- Credential configuration: `ait-transcript`, type `AitTranscriptCredential`
- Issuer display: "AIT University Registrar"; Mimoto issuer id `AITUniversity`
- Adapter CSV: `adapter/student_identity_data.csv`, one row per degree, keyed by the `id` column (the Keycloak username)
- Certify data-provider plugin, in `certify-csvdp-student.properties` (contracts.md section 2a; these six keys and nothing else; edit the file and restart Certify, `docker compose restart certify`):
  - `mosip.certify.integration.data-provider-plugin`: `GatewayDataProviderPlugin`
  - `mosip.certify.integration.scan-base-package`: `asia.mosip.issuer.gateway.plugin`
  - `mosip.certify.gateway.url`: the Gateway's base URL, `http://gateway:8000`
  - `mosip.certify.gateway.auth-token`: the shared bearer token; must equal `GATEWAY_AUTH_TOKEN` below (the committed value is test-only)
  - `mosip.certify.gateway.connect-timeout-ms`: `2000`
  - `mosip.certify.gateway.read-timeout-ms`: `15000` (the Gateway makes three adapter calls of at most 3 s each and a database write with a 3 s connect timeout, 12 s in the worst case)
- Gateway settings, in `gateway.env` (the `gateway` service's `env_file`; edit the file and recreate the container, `docker compose up -d gateway`):
  - `GATEWAY_ENABLED_SCOPES`: space-separated scopes the Gateway serves, each a credential type registered in `gateway/credential_types.py`; here `ait_transcript_vc_ldp`
  - `GATEWAY_ADAPTER_URL`: the data adapter's base URL, `http://adapter:8000` (the mock adapter)
  - `GATEWAY_AUTH_TOKEN`: the shared bearer token the plugin sends (contracts.md section 2a), equal to `mosip.certify.gateway.auth-token` above; the committed value is test-only, for local runs and CI
  - `GATEWAY_DATABASE_URL`: Certify's Postgres (`database`, database `inji_certify`) with the stack's `postgres` superuser; the Gateway creates its `gateway` schema there on start
- Test fixtures, in `smoke.json`, a list with one entry per credential type (here one): `credentialConfig` (`ait-transcript`, the only configuration Certify must list), `scope`, `eligible` (`ait-2026-0001`, issued and verified, then tampered), `refused` (each persona with the check that fails: `ait-2026-0002` `no_holds`, `ait-2026-0003` `conferred`, `ait-2026-0004` `zero_balance`), `tamper` (the claim paths changed in the tampered copies: `fullName`, `courses[0].courses[0].grade`), `mimotoTemplate` (the Inji Web PDF template `smoke.sh` expects in `vc-stack/config/`)
